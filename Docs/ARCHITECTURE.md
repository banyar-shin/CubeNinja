# Architecture

## Runtime Split

- `CubeNinja.Core`
  - `ScoreComboTracker` is pure C# combo state and score multiplier timing.
- `CubeNinja.Data`
  - `CubeTypeDefinition`, `CubeSpawnSettings`, and weighted cube type data.
  - Defines scoring cubes versus danger cubes through `CubeClickOutcome`.
- `CubeNinja.Gameplay`
  - `CubeTarget` owns click/miss detection, Rigidbody launch state, side-bound reflection, translucent cube material setup, and black cube edge geometry.
  - `ComponentPool<T>` handles target reuse.
  - `AudioFeedbackPlayer` creates simple runtime sound effects without imported clips.
- `CubeNinja.Run`
  - `CubeNinjaRunDirector` owns run lifecycle, spawning, scoring, lives, high score persistence, background setup, and service wiring.
  - `CubeNinjaRuntimeBootstrap` keeps the scene runnable when runtime services are missing.
- `CubeNinja.UI`
  - `HudPresenter` builds UGUI/TextMesh Pro start menu, HUD, game-over screen, life display, score popups, click pixels, red edge glow, and text border layers.
- `CubeNinja.Editor`
  - Menu tools for starter content generation and definition validation.
- `CubeNinja.Tests.EditMode`
  - Focused tests for pure combo scoring behavior.

## Run Flow

1. `CubeNinjaRunDirector.Awake` loads the saved high score, ensures scene services, creates the combo tracker and cube pool, then enters the start menu.
2. The start menu is generated by `HudPresenter` and populated from the active `CubeSpawnSettings`.
3. Starting or restarting a run clears active cubes, resets score/lives/combo state, hides the start menu, plays the start sound, and begins spawning.
4. Each spawn picks a weighted `CubeTypeDefinition`, launches a pooled `CubeTarget` from below the viewport, and clamps its horizontal bounds to the camera view.
5. Clicking a scoring cube registers a combo hit, adds `pointValue * multiplier`, updates high score, shows a floating popup, and plays a pitched score sound.
6. Clicking a danger cube resets combo and costs 1 life.
7. Missing a scoring cube resets combo and costs 1 life. Missing a danger cube has no penalty.
8. At 0 lives, the director ends the run, clears active cubes, plays game-over audio, and leaves the red edge glow visible behind the game-over UI.

## Rendering And UI

- The camera is orthographic and the shrine background is a runtime quad scaled to cover the viewport.
- The background texture is loaded from `Resources/Backgrounds/shrine_background`.
- Cube faces use an unlit transparent material with a white texture and per-instance color through `MaterialPropertyBlock`.
- Cube edge lines are separate child cube renderers so transparent faces still read as cubes.
- Cube colliders are triggers for click detection; physical cube-to-cube collision is not part of gameplay.
- All UI is created in code. The scene does not rely on pre-authored Canvas objects.
- Text borders are implemented as black duplicate TMP labels synchronized behind each visible label. This avoids TMP outline material issues and keeps styling consistent across HUD, menus, buttons, and floating popups.

## Persistence And Assets

- High score is local-only via `PlayerPrefs` key `CubeNinja.HighScore`.
- Sound effects are generated from code in `AudioFeedbackPlayer`.
- The only required imported visual asset is the shrine background image in `Assets/_Game/Resources/Backgrounds/`.

## Rules

- Keep tuning in ScriptableObjects rather than hard-coded scene state.
- Keep score/combo math testable outside Unity scene objects.
- Keep scenes small; the run director creates default services when references are missing.
- Keep runtime visual helpers local to gameplay/UI code unless they become shared systems.
- Use additive component behaviour instead of inheritance-heavy target types.
- Keep assembly definition references explicit and one-directional.
